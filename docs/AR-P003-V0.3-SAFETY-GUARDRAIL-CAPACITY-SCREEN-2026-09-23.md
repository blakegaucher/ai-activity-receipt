# AR-P003 v0.3 — Critical-False-Clearance Guardrail Capacity Screen

> **Status:** Development-only decision support; not a frozen power analysis.  
> **Date:** 2026-09-23  
> **Scope:** Stress-test the proposed +2 percentage-point critical-false-clearance guardrail before any owner selection of `effect_precision_target`.

## Why this screen was added

The current proposal bundles three project-specific thresholds:

- +5pp minimum practically important Receipt-specific supported-completion benefit;
- 3pp accuracy noninferiority margin only if a separate speed claim is later activated;
- +2pp maximum acceptable increase in critical false clearance.

The earlier effect-target preflight showed that +5pp already implies a substantial study under many plausible baselines. The +2pp safety guardrail could be more demanding, so this note screens its resource consequence separately.

## Approximation

This screen assumes:

- equal condition sizes;
- true Receipt-vs-comparator critical-false-clearance difference = 0;
- one-sided alpha = 0.025;
- power = 0.80;
- proposed upper margin = +0.02;
- illustrative design-effect multiplier = 1.5;
- illustrative unusable-observation allowance = 10%;
- 24 cases per reviewer;
- balanced three-condition capacity translation.

The independent-observation approximation is:

`n ≈ (z_(1-alpha) + z_power)^2 × [2 p (1-p)] / margin^2`

The three-condition reviewer-equivalent is then only:

`ceil(3 × adjusted_n_per_condition / 24)`

This is **not** a crossed reviewer × case power result.

## Results

| Comparator critical-false-clearance rate | Raw n / condition | Adjusted n / condition | Rough 3-condition reviewer-equivalent |
| ---: | ---: | ---: | ---: |
| 0.5% | 195.2 | 326 | 41 |
| 1% | 388.5 | 648 | 81 |
| 2% | 769.2 | 1,282 | 161 |
| 5% | 1,864.1 | 3,107 | 389 |
| 10% | 3,532.0 | 5,887 | 736 |
| 20% | 6,279.1 | 10,466 | 1,309 |

## Interpretation

The +2pp guardrail behaves very differently depending on the underlying event rate.

- If critical false clearance is genuinely rare (around 0.5–1%), this rough screen is not obviously more demanding than the proposed +5pp supported-completion target.
- Around 5% baseline false clearance, the screen is already roughly 389 reviewer-equivalents under the same illustrative inflation assumptions.
- At higher event rates, the simple capacity requirement becomes very large.

This creates a design dependency that should be resolved **before** final sample-size freeze: the study needs a plausible pre-execution sensitivity range for the critical-false-clearance rate and a frozen uncertainty rule for judging the +2pp margin.

## Rare-event warning

For very low event rates, a normal approximation can be poor and zero-event cells are plausible. The final safety analysis may require a different method and crossed-effects simulation. This screen must not be used as the final inferential design.

## Consequence for the pending owner decision

This result does **not** reject or select the +2pp guardrail.

It does show that the threshold bundle cannot be evaluated only through the +5pp primary-benefit target. Before final design freeze, the safety guardrail should receive its own crossed reviewer × case sensitivity analysis across plausible critical-false-clearance rates.

The repository should therefore keep:

`effect_precision_target = unresolved`

until the owner explicitly selects the threshold bundle.

