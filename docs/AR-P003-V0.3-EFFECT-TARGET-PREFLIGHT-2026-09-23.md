# AR-P003 v0.3 — Effect-Target Preflight

> **Status:** Development-only decision support; not a frozen power analysis.  
> **Date:** 2026-09-23  
> **Purpose:** Stress-test the proposed +5 percentage-point supported-completion threshold before any owner selection of `effect_precision_target`.

## Scope

This note uses the repository's existing independent-observation screening approximation in `benchmark/arp003_v0_3/plan_sample_size.py`.

It does **not** replace the crossed reviewer × case planner, does not estimate the true human effect, and does not freeze reviewer count, case count, allocation, stopping, or the final analysis model.

Assumptions used only for this screen:

- two-sided alpha = 0.05;
- power = 0.80;
- design-effect multiplier = 1.5;
- unusable-observation allowance = 10%;
- 24 cases per reviewer;
- balanced three-condition allocation.

The 1.5 design effect and 10% unusable allowance are existing illustrative repository assumptions, not frozen estimates.

## +5 percentage-point Receipt-specific benefit screen

The proposed threshold is mapped to `receipt_vs_structured`.

| Structured success | Receipt success | Raw independent n / condition | Adjusted n / condition | Rough 3-condition reviewer-equivalent at 24 cases/reviewer |
| ---: | ---: | ---: | ---: | ---: |
| 0.50 | 0.55 | 1564.7 | 2608 | 326 |
| 0.60 | 0.65 | 1470.5 | 2451 | 307 |
| 0.70 | 0.75 | 1250.7 | 2085 | 261 |
| 0.75 | 0.80 | 1093.7 | 1823 | 228 |
| 0.80 | 0.85 | 905.4 | 1509 | 189 |

The reviewer-equivalent column accounts only for the fact that, in a balanced three-condition design, approximately one third of reviewer-case observations fall in each condition:

`ceil(3 × adjusted_n_per_condition / 24)`

It is **not** a crossed-effects power result.

## Candidate reviewer-count capacity

With 24 cases per reviewer and balanced three-condition assignment:

| Reviewers | Total reviewer-case observations | Approx. observations / condition |
| ---: | ---: | ---: |
| 108 | 2592 | 864 |
| 216 | 5184 | 1728 |
| 324 | 7776 | 2592 |
| 432 | 10368 | 3456 |

Under the illustrative 1.5 design effect / 10% unusable screen:

- 108 reviewers is below every +5pp scenario in the table;
- 216 reviewers clears the highest-baseline 0.80→0.85 screen but not the 0.75→0.80 screen;
- 324 reviewers clears the 0.60→0.65, 0.70→0.75, 0.75→0.80, and 0.80→0.85 screens and is only slightly below the 0.50→0.55 screen;
- 432 reviewers clears all listed independent-observation screens.

These comparisons are capacity checks only. Reviewer/case dependence can materially change actual information.

## Interpretation

The +5pp threshold is methodologically usable as a smallest practically important effect, but it is not a small-study target under the current three-condition architecture.

This is a useful property rather than evidence for or against the threshold: it makes the resource consequence explicit **before** confirmatory outcomes are available.

The current repository therefore should not freeze 108 reviewers merely because that count appeared in an earlier planning center. If +5pp is selected, the crossed simulation must evaluate larger candidate counts and heterogeneity sensitivity before allocation is frozen.

## Critical-false-clearance guardrail

The proposed +2pp critical-false-clearance threshold is a separate safety decision, not part of the binary primary endpoint.

A 2pp safety margin may become more sample-size demanding than the +5pp benefit target depending on the underlying false-clearance rate and the final inferential rule. The repository does not yet contain a frozen noninferiority/safety-margin power implementation for this endpoint.

Before final sample-size freeze, the analysis plan therefore still must specify:

- the comparator(s);
- the expected or sensitivity range for critical-false-clearance rates;
- one-sided/two-sided uncertainty rule as appropriate;
- how the +2pp guardrail is judged;
- crossed reviewer/case dependence handling.

No sample-size conclusion for the safety endpoint is made in this preflight.

## Separate speed-claim margin

The proposed 3pp accuracy noninferiority margin remains dormant unless a separate speed claim is preregistered. It should not add sample-size requirements to the core study unless that claim is explicitly activated before execution.

## Preflight conclusion

The proposal remains internally defensible as a **project-specific preregistration threshold bundle**, with two cautions:

1. selecting +5pp implies that the final crossed-design planning grid must include reviewer counts materially above 108 under plausible baselines/heterogeneity;
2. the +2pp critical-false-clearance guardrail requires its own uncertainty/power treatment before final sample-size freeze and may become the binding information requirement.

This note does not select `effect_precision_target`.
