# AR-P003 v0.3 — Comparison-Condition Decision

> **Decision date:** 2026-09-20  
> **Decision authority:** Blake Gaucher / project owner  
> **Status:** Selected methodology decision; development-only implementation, not a frozen or executed study.

## Selected candidate

`three_condition_structured_control`

The selected comparison design has three conditions:

1. **raw** — heterogeneous underlying evidence only;
2. **structured** — a neutral structured event table plus the same underlying evidence;
3. **receipt** — the AI Activity Receipt plus the same underlying evidence.

## Rationale

The neutral structured-control condition is intentionally included so AR-P003 can distinguish two different effects:

- benefit from generic organization/structuring of the underlying evidence;
- additional benefit, if any, attributable specifically to the Activity Receipt presentation and semantic layer.

This is an explicit preregistration methodology choice. It is not inferred from whichever runner implementation happened to exist first.

## Preserved conflict / rejected candidate

The earlier repository draft implemented `two_condition_current`:

- raw/underlying evidence only;
- the same evidence plus Receipt.

That candidate remains preserved in the methodology ledger and historical Git record, but it is not selected.

The earlier project research review recommended the three-condition structured control. The owner has now explicitly selected that candidate.

## Required implementation consequence

The methodology impact map classifies this candidate as `requires_versioned_change`.

Before this comparison-condition gate may be considered implemented, the repository must contain a consistent versioned three-condition protocol, assignment generator, case-package/structured-control contract, reviewer bundle/runner path, response/analysis contracts, scorer, merge path, evidence-symmetry audit, and crossed-design planning support.
